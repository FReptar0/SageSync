<objective>
Each server keeps its Sage→Fracttal warehouse mapping in its own file outside git (`config.local.json`), selected through a new optional env var, `CONFIG_PATH`. Deploys are a `git fetch` plus `git reset --hard` of the obfuscated dist, so today every deploy silently puts back the repo's `config.json` mapping (GRAL → ALM-AMP, with warehouse auto-creation on). With this change a deploy can no longer do that.

The plan also ships `scripts/install-service.ps1` in the dist. Its default `-InstallDir` becomes the folder the script lives in.

Purpose: the user deploys to the client's PRODUCTION server this week. Next week the initial full load runs by hand, and then the Servy service is enabled with the automatic daily schedule (12:00/16:00/23:00). If a deploy reverted the mapping, that schedule would create ALM-AMP in the client's production Fracttal and sync there. Putting the production mapping in the repo is not acceptable: the test server deploys the same branch and might share the Fracttal tenant.

1. `CONFIG_PATH` in ConfigManager, the active-file backup and checklist in maintenance, `config.local.json` in `.gitignore`, and 8 new tests.
2. The dist build ships `install-service.ps1` and ignores `config.local.json`; `install-service.ps1` gets its new default `-InstallDir`; the local build is checked without pushing.
3. Spanish docs: the production recipe and procedure.
