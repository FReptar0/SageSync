# Milestone v1.1: License Control System

**Status:** ✅ SHIPPED 2026-04-08
**Phases:** 1–2
**Total Plans:** 4

## Overview

Tersoft can remotely control whether SageSync operates at any client site. A tampered, expired, or revoked license prevents the app from running. This milestone added a full license-validation subsystem (HMAC-signed, three-state cache, periodic re-validation) and an enforcement surface (Express middleware, cron guard, status endpoint, and operator-visible UI banner/overlay).

## Phases

### Phase 1: Validator Core

**Goal**: The app validates its license on startup and refuses to start if the license cannot be confirmed.
**Depends on**: Nothing (first GSD phase)
**Requirements covered**: CFG-01, CFG-02, LIC-01, LIC-02, LIC-03, LIC-04, ENF-03, ENF-04
**Plans**: 2 plans

Plans:

- [x] 01-01: Config module, env validator, and LicenseValidator port from sageconnect
- [x] 01-02: Unit tests for all 8 phase requirements and entry point wiring

**Success Criteria (all met):**

1. App reads `LICENSE_API_URL`, `HMAC_SECRET`, and `SAGESYNC_API_KEY` from environment and passes them to the validator.
2. App exits with code 1 on startup when license validation fails after 3 retries with exponential backoff.
3. A valid license response with a correct HMAC-SHA256 signature and fresh timestamp (under 5 minutes old) results in `VALID` state.
4. A network failure during validation transitions state to `ERROR`, and after 24h in `ERROR` state the app treats the license as `INVALID`.
5. A license server hostname that resolves to a private or loopback IP triggers a logged warning (non-blocking).

**Details:**

- Ported `LicenseValidator` from SageConnect (`sageconnect/src/services/LicenseValidator.js`) and adapted to SageSync's config shape; removed `sendLicenseAlert` and `nodemailer` (no email alerts — log warnings only).
- `validateEnv` checks all three groups (license, database, fracttal) — fail-fast with the complete error list at boot.
- `LicenseValidator` uses the Winston logger singleton (not `LogGenerator`) — consistent with SageSync logging.
- `axios.create()` runs at module load time, so the `licenseClient` is created once and must be controlled via `jest.mock` factory (not `beforeEach` assignment) in tests.
- Two-tier license gate established: startup gate (retries + exit) at boot, periodic re-validation on each cron sync cycle.

### Phase 2: Enforcement Surface

**Goal**: Every operational path in the app is gated by license state, and the current state is visible to operators.
**Depends on**: Phase 1
**Requirements covered**: ENF-01, ENF-02, STS-01, STS-02
**Plans**: 2 plans

Plans:

- [x] 02-01: `requireLicense` middleware, status endpoint, cron log fix, and tests
- [x] 02-02: Frontend license banner, overlay, expiry badge, and polling

**Success Criteria (all met):**

1. Any API request (except `GET /api/system/license`) returns HTTP 503 when license state is `INVALID` or `ERROR-past-TTL`.
2. Cron sync cycles are silently skipped and a warning is logged when license is not `VALID`.
3. `GET /api/system/license` returns a JSON object with current state, active flag, `expiresAt`, and `lastChecked` — always, regardless of license state.
4. The web dashboard displays a visible banner when license state is `INVALID` or a license is expiring.

**Details:**

- `requireLicense` exemption for `/api/system/license` lives in the `main.js` wrapper, not inside the middleware — middleware stays single-responsibility.
- License gate mounted before `express.static` in `main.js` so HTML serving is also blocked when license is invalid.
- Integration tests mock `src/app` to prevent `validateEnv()` `process.exit` at module load (syncController dependency chain).
- Frontend banner z-index 1050 sits above overlay z-index 1049 — banner stays visible even when the overlay is active.
- Expiry countdown badge only renders for `VALID` state within 30 days — avoids confusing badges on `INVALID`/`ERROR` states.
- `checkLicenseStatus()` polls `/api/system/license` every 60 seconds from the dashboard.
- Cron guard log level was fixed from `error` to `warn` (license-skipped cycles aren't actually errors).

## Milestone Summary

**Decimal Phases:** None.

**Key Decisions:**

- Port `LicenseValidator` from SageConnect (reference implementation at `sageconnect/src/services/LicenseValidator.js`) rather than build from scratch — proven HMAC + freshness logic, well-tested.
- Reuse `sageconnect-license.vercel.app` as the license server — only needed to register a new `SAGESYNC_API_KEY` client.
- No email alerts (user opted out) — log warnings to Winston only.
- `validateEnv` validates **all three** env groups (license + database + fracttal) and fails fast with the full error list.
- Two-tier gate: startup (retry + exit) AND periodic (no exit) on each cron tick.
- `requireLicense` exemption logic kept in the `main.js` mount wrapper — middleware itself stays single-responsibility.
- Frontend: banner + overlay layered separately (z-index 1050 / 1049) so the banner remains visible during overlay; expiry badge only on VALID-within-30-days.

**Issues Resolved:**

- Original blocker — “Need new `SAGESYNC_API_KEY` registered on the license server before Phase 1 can be tested end-to-end” — resolved during Phase 1 execution (key registered, end-to-end smoke passed).
- Cron-guard log level miscategorized as `error` for license-skipped cycles — corrected to `warn` in 02-01.

**Issues Deferred:**

- `tests/services/fracttalClient.test.js` — `updateWarehouseItem` test asserts PUT to `/items/item1`, but the current implementation calls `/inventories_adjustment/item1`. Pre-existing before Phase 2 (confirmed via git stash). See `.planning/phases/02-enforcement-surface/deferred-items.md`. Carry into v1.2 as a focused tech-debt task.

**Technical Debt Incurred:**

- Mixed language by file age (Spanish in older files: `app.js`, `sageService.js`, `fracttalClient.js`, `maintenance.js`, `configManager.js`; English in newer v1.1 files: `LicenseValidator.js`, `requireLicense.js`, `validateEnv.js`, `license.js`). User-facing logs remain Spanish across the board. Documented in `CLAUDE.md` — no immediate cleanup, but flag for future contributors.
- Deprecated FracttalClient methods (`createInventoryItem`, `updateWarehouseItem`) still present alongside the canonical replacements (`createInventoryWithWarehouse`, `associateItemToWarehouse`, `adjustInventoryStock`). Pre-existing v1.0 debt, not introduced by v1.1. Removal candidate for v1.2 if no remaining callers found.
